# 检修任务步骤局部修订实现计划

## 目标

实现已批准的“手册优先、局部步骤修订”流程：员工在分步推进看板点击一个按钮，用文字或语音转写描述问题；系统解析范围、匹配手册、返回预览；员工确认后只替换允许修改的步骤。当前步骤记录作为管理端和自动审核的唯一事实来源。

## 实施顺序

### 1. 数据库与领域模型

- 新增 `task_step_revision` 表及增量 SQL：请求文本、状态、范围、Agent 原始结果、前后快照、错误、确认/应用时间。
- 给 `task_step_record` 增加最近修订提示和修订关联字段，保持原有步骤状态字段语义不变。
- 增加 Java entity、mapper、VO/DTO，补充 JSON 类型处理和索引。
- 为修订状态、步骤修订状态建立常量，避免散落字符串。

### 2. FixAgent 修订服务

- 新增步骤修订请求/响应 schema。
- 新增修订服务：解析自然语言范围、过滤状态、检索手册、逐步判定“手册一致/按手册纠正/现场描述重生成”。
- 强制输出原 stepId、sortOrder、处理类型、来源、前后内容摘要和风险提示。
- 范围不明、手册服务失败、输出无法解析时返回 clarification/failed，不生成可应用草案。
- 在 MQ consumer 中增加修订分析队列及结果回传，复用现有 RabbitMQ 拓扑和通知机制。

### 3. Java 修订服务与接口

- 新增 `POST /weixiu/task/{taskId}/step-revisions`、查询、确认、取消接口。
- 创建请求时检查权限和任务状态，保存 `ANALYZING` 记录并发送异步消息。
- 结果回调保存不可变预览，并发布“预览可用/失败”通知。
- 确认应用时在事务内锁任务和步骤，重新验证快照、状态、stepId、sortOrder 和预览有效期。
- 只更新实际变化且状态允许的步骤；清理这些步骤的执行证据并置为 `PENDING`；范围外及未变化步骤保持原状。
- 将 `task_step_record` 作为管理端/用户端当前事实来源；任务关闭后拒绝修订。
- 确认最终结果时继续从最新步骤构建 `evidenceBundle`，使用新的 `evidenceVersion` 触发自动审核；旧回调不得覆盖新版本。

### 4. 前端交互与通知

- 在 `UserTaskDetail.vue` 的分步推进看板增加唯一“修改步骤”按钮和轻量弹窗。
- 实现输入、分析中、预览、确认、失败/过期等状态；预览中展示锁定步骤、手册处理类型、差异和会被重置的证据。
- 在 `TaskStepCard.vue` 展示修订提示字段，不新增重复入口。
- 在 `maintenanceTask.js` 增加修订 API；在 `notifyStore` 增加 `stepRevision` 任务类型和预览元数据。
- 修改 `RunningTasksTray.vue`：预览可用状态保持可点击，点击后定位任务并打开预览；应用成功/失败后复用现有收起策略。
- 刷新页面后恢复进行中的修订通知，并处理预览过期。

### 5. 测试与验证

- Java：范围解析、状态锁定、手册分支、快照并发、确认幂等、过期、权限、旧审核版本回调。
- FixAgent：结构化输出契约、歧义澄清、手册失败不降级、stepId/sortOrder 一致性。
- 前端：弹窗状态、预览确认、通知点击重开、步骤提示和构建。
- 集成验证：修订后管理端任务详情读取新步骤；最终结果确认生成新证据版本并自动审核新步骤。

## 关键实现约束

- 不改变任务主状态为整任务 `GENERATING`。
- 不允许修改 `SUBMITTED`、`AI_PASSED`、`COMPLETED`、`SKIPPED` 步骤。
- 不允许 Agent 直接落库；所有应用由 Java 事务完成。
- 不允许用手册服务失败作为自由生成的理由。
- 不修改管理员现有审批工作流，不新增管理员页面。
